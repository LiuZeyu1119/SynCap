# SynCap SDK 本轮交付与验收

日期：2026-09-13。基础控制 ABI 0.1.0；Android 媒体 0.1.1，其余平台模块为 0.1.0。此记录优先于旧发行目录与历史测试记录，不是“四端所有功能全部完成”的声明。

## 可独立接入的模块

| 模块 | 实际内容 | 验证范围 |
| --- | --- | --- |
| Rust core / CLI | HTTP 能力/状态/存储/方向、采集、会话、校验断点导出 | Release workspace 70 项通过；真实 Wi-Fi 导出 |
| Android `syncap-sdk` | 同一 Rust 核心的 Kotlin 异步绑定 | 手机原生 7 项；物理相机采集/停止/导出/续传通过 |
| Android `syncap-bluetooth-android` | 发现、系统配对入口、GATT/RFCOMM、配网与设备支持的离线命令 | 手机协议/生命周期测试通过；Tina RFCOMM 扫描、配置写入通过；GATT 真机未测 |
| Android `syncap-media-android` | LibVLC 预览、原始 NV12 棋盘格采样及 fisheye 双目标定 | 手机标定 6 项通过；0.1.1 两路真实预览三次冷启动及 Maven 包 60 秒测试通过；长期稳定性未通过 |
| Apple `SynCapSDK` | Swift async 控制/采集/导出、XCFramework | macOS 6 项；已有真实 Wi-Fi 导出；未用 iPhone 真机验收 |
| Apple `SynCapBluetooth` | 独立 CoreBluetooth GATT | macOS 协议/取消 4 项通过，iOS/模拟器构建通过；不支持当前 Tina 的 Classic 配网 |
| iOS `SynCapMedia` | 独立 UIKit/MobileVLCKit 预览页面 | iOS/模拟器构建通过；没有 iPhone 真机验证 |

原 Android/iOS App 的预览与 Android 标定页面已移到 SDK，App 引用同一份源码。移动 App 的 HTTP/蓝牙桥接未全部迁移，不能把其旧测试算作 SDK 测试。SDK 没有依赖 ADB，ADB 只用于本轮测试部署与取证。

## 本轮手机与全志实测

设备为 OPPO PLP110 与 Tina 双目服务 0.2.5，经真实局域网通信，没有 HTTP USB 转发。未烧录镜像、未更改 qgapp/相机编码参数、未删除用户录制或清空 App 数据。

1. 独立手机 SDK 单次开始，设备 `elapsedMs` 和字节数连续增长，单次停止后状态 completed。
2. 会话 `ses_19700102_011552_d77997`：**12.953 秒，12 个非零数据文件，9,601,483 B**。SDK 导出含清单 9,604,118 B，逐文件大小/哈希通过。
3. 新目录预置 131,071 字节部分文件再导出，12 个文件全部验证通过。是模拟断点，不是断网/后台恢复验收。
4. MCAP 独立检查：左 360、右 359、IMU 9738、音频 191 条；末尾多 1 个左目消息。文件传输完整，不代表严格全帧同步或每个 GOP 起点已验证。
5. 独立蓝牙 SDK 自动走当前设备支持的 RFCOMM，扫描到 5 个 Wi-Fi，配置写入后返回 connected 与实际 IP。配网完成后手机也必须能访问头环网络，SDK 不擅自切换宿主网络。
6. 原始标定测试验证实际 NV12 棋盘格输入接受、重复姿态拒绝、哈希/来源/方向/尺寸条件，以及合成 120 mm 已知双目基线。不是实拍镜头 RMS 结论。

Android R8 独立测试宿主的 7 项原生测试通过。首次因 AndroidJUnitRunner 引用的 `androidx.tracing.Trace` 在共享宿主中被裁剪而崩溃；只在显式 `testReleaseSdk=true` 的测试宿主规则中保留该 ABI 后复测通过。没有给基础 AAR 加全局 keep，不能据此宣称任意生产宿主的全部压缩配置都已运行验证。Android/iOS App 引用媒体模块后均已构建；Android 单元测试及 28 个受保护 runtime 文件检查通过。

真实预览测试最初因手机 Wi-Fi 关闭而在 HTTP 阶段失败，恢复同网段后原生控制 7 项通过。一轮维持前台约 15 秒仍未出帧，属于真实失败；另一轮被来电和页面切换打断，两路显示“已暂停”。这些历史失败保留；后续独立复现与修复见下节，未将所有失败归因于手机切后台。

另存故障 ring 后正常重启，电脑直连左目 TCP，ffprobe 解码出 3,855 帧、1600×1200，起始出现 PPS/参考帧缺失警告；其推断 `r_frame_rate=1200000/1` 不是物理帧率，裸流按时间截止不可靠，本次探测实际持续约 2 分钟。随后设备再次进入不完整片段保护，保留 `tina-pc-preview-fault-ring/` 和日志。电脑可解码不代表 Android 已能渲染，帧率推断异常也未证明就是手机黑屏根因。没有据此盲改视频码流或播放器参数。

采集/蓝牙测试使用宿主的最长 240 秒 CPU 唤醒锁，测试后释放；库不隐式持锁。期间另一次无前台蓝牙测试停住并被终止，前台复测通过；没有将它宣称为生产后台可靠性修复。初次采集验收还修正了对可选 `exportAvailable` 字段的错误要求，未放宽实际文件校验。

## Android 媒体 0.1.1 补测

在保持前台、TCP 两路已连接、设备持续产生数据的条件下，旧配置重复出现 displayed/decoded 均为 0。详细日志在选中硬件 HEVC 解码器后，进入字幕字体初始化，出现 Fontconfig 配置错误而无后续帧。禁用相机预览不需要的字幕、OSD 和文字渲染器后恢复出帧；原生相机标签与关闭按钮不受影响。这是有前后对照的有效修复，不是对第三方库内部锁根因的完整证明。

修复仅为 `--no-spu`、`--no-osd`、`--text-renderer=none`，未修改硬解、分辨率、码率、相机帧率或录制数据。去掉临时 verbose 日志后完成三次冷启动；新发布 Maven 0.1.1 实测连续 60 秒，两路显示计数从 [26, 8] 增至 [1788, 1791]，随后资源释放通过。这是有界前台测试，不是零丢帧或全天稳定性声明。

期间通过 Rust CLI 在同一真实 Wi-Fi 采集 `ses_19700102_031926_cb370c`：75.897 秒、74 个数据文件、46,313,776 B；导出含清单 46,325,822 B，74 文件大小与 SHA-256 均通过。录制与 60 秒预览部分重叠，停止发生在该预览测试结束之后。原始 HEVC 每路 2,220 条消息，可解码 2,219 帧、1600×1200；起点有 PPS/参考帧缺失警告，因此传输完整不等于视频起始 GOP 无损。

同一媒体修复已进入 App 1.0.3（versionCode 4），覆盖安装保留数据，APK 约 81 MiB，无新增依赖。手机从真实 App 界面开启预览，两路显示帧持续增长约 112 秒，正常关闭并释放引擎。另一次 `ses_19700102_033051_b1a236` 的开始/停止/导出均在 App 预览开启期间由 Rust CLI 发起：45.457 秒、44 个数据文件、27,718,911 B，导出含清单 27,726,395 B，全部哈希通过。这验证 App 预览与 SDK 采集并发，不等同于点击 App 采集按钮的交互验收。

同一 App 进程关闭后重新打开，两路继续显示超过两分钟，末次显示计数 [4188, 4148]，再次关闭后引擎释放。另做独立 App 按钮测试：单击开始后计时从 00:00:04 增至 00:00:39，设备 `elapsedMs` 从 4,925 增至 39,722，字节数同步增长；单击停止后返回空闲。会话 `ses_19700102_033650_e60d15` 为 41.541 秒、40 个非零数据文件、24,983,016 B；再由 SDK CLI 导回电脑，含清单 24,989,883 B，40 文件哈希通过。没有将 CLI 导出称为 App 导出按钮测试。

更新后的媒体原始输入/标定 6 项真机测试再次通过（0.764 秒），App 30 项 JVM 测试与 28 个受保护 runtime 文件检查通过。Gradle 离线 connected 测试因本机缺少 UTP 依赖未启动；改为安装同一个已构建测试 APK 并用 ADB instrumentation 跑完 6 项，不依赖下载 UTP。

设备端约运行 21 分钟又出现 gyro silent >3s、重启 cap_en、编码缓冲区满，退出时线程停在 `sunxi_twi_drv_wait_complete`，服务进入不完整片段保护。这支持 IMU/I2C 与编码停滞相关，但尚未证明硬件/驱动具体根因。保存日志及故障 ring 后正常重启恢复；已移除本轮新增的唯一临时日志配置，原厂 qgapp 与服务二进制未改。没有烧录固件或删除用户采集。

## 仍然存在的限制

公开发布整理：App 1.0.4（versionCode 5）仅移除了未被代码引用的私有实拍 PNG 并更新版本号，JavaScript/CSS 构建文件与上述 1.0.3 相同；原素材和原 APK 留在本机、不公开。1.0.4 完成构建与主机回归，以上物理设备测试对应 1.0.3，不混淆为新一轮真机验收。SDK 文档与 fixture 的真实设备序列号已匿名化，SDK 二进制及 ABI 未改变。

- 原厂 qgapp 在本轮空闲约 26 分钟、另次约 16 分钟后停滞；电脑预览期间又复发，服务进入故障保护。保存日志后正常重启能暂时恢复，不是固件问题已修复；SDK 保留 recoveryRequired/rebootRequired，不会自动清除或重启。
- 设备时间仍为 1970，使用设备单调时长 `elapsedMs`；不要用手机墙钟减设备时间。未测物理曝光到外部时钟误差，当前 Tina 不支持 PTP。
- Tina 缺少同步原始 NV12 标定快照接口，不能拿预览替代。Apple 标定算法、鸿蒙绑定仍未实现。
- 当前 Tina Classic 配网不能由 iPhone CoreBluetooth 使用；需要设备提供真实 GATT 服务及 iPhone 实测。RoboBaton 本轮未连接，不能保证新模块的所有 GATT/离线分支已在其上运行。
- 系统授权、文件选择、后台服务、交互和长期稳定性验收由接入项目与硬件共同完成，不由库测试代替。

## 使用与产物

Android ZIP 含本地 Maven 仓库、源代码 JAR、独立消费示例、文档；无需原 App 源码即可通过 Maven 坐标接入。Apple 控制/BLE ZIP 含独立 Swift Package、XCFramework 和测试；iOS 媒体包单独发行，避免给只做控制的应用引入大型视频依赖。终端提供 macOS arm64 CLI；其他系统可从 Rust 源码构建，未附未经验证的 Windows/鸿蒙二进制。

Rust ZIP 包含独立 workspace、三个 crate 与全部核心测试，不包含原 App。发行目录 `README.md` 为入口，`SHA256SUMS` 用于交付文件校验。Android 与 Apple 控制/BLE 解包后已分别在独立目录构建/测试，而非仅构建仓库内部模块。

构建开发包仍需 Android/Xcode/JDK 工具链及首次公开依赖下载/预缓存；安装后局域网控制和导出不需要公网。开发包不包含用户录像、密码、手机截图或固件备份。

证据保存在仓库 `artifacts/2026-09-13-sdk-completion/` 和 `artifacts/2026-09-13-sdk-preview-fix/`；历史失败证据继续保留，未覆盖成通过记录。本记录随包提供，发行目录另附 SHA256SUMS。
